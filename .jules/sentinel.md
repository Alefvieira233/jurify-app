## 2026-07-21 - Security Audit Scan Omission of Multiple Header Blocks in Vercel JSON
**Vulnerability:** The security audit script (`scripts/security-audit.cjs`) used simple array element access (`vercelJson.headers?.[0]?.headers`) to parse HTTP security headers. This meant it only validated security headers defined in the first route configuration block of `vercel.json` (the `/assets/(.*)` route which typically only holds a Cache-Control policy), completely failing to inspect the second route configuration block (the global `/(.*)` route) containing critical security headers (CSP, HSTS, X-Frame-Options, X-Content-Type-Options). This lead to a scanner gap/failure reporting false failures.
**Learning:** Checking hardcoded indices of configuration files (like `vercelJson.headers[0]`) assumes a strict structural sequence and does not account for routing/matching blocks common in infrastructure configs. Security validation scripts must utilize exhaustive list flattening to capture all definitions.
**Prevention:** Always use exhaustive array transformations like `.flatMap(h => h.headers || [])` to collect and verify security configurations across all route/path descriptors in deployment and routing profiles.

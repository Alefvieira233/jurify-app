## 2026-05-25 - PII Leakage via Truncation-Redaction Race
**Vulnerability:** Personally Identifiable Information (PII) like CPFs, CNPJs, or Credit Cards can leak into diagnostic logs even when redaction is implemented, if the string is truncated (e.g., via `.substring()`) before the redaction utility is called.
**Learning:** Regex-based redaction depends on matching complete patterns. If a truncation operation cuts through a sensitive token (e.g., "123.456.789-00" becomes "123.456."), the pattern no longer matches, and the partial data is logged in cleartext. This creates a race condition between the desire to limit log volume and the requirement to protect data.
**Prevention:** Always apply PII redaction (`redactPII`) to the full, original content string BEFORE performing any character-based truncation for logging or diagnostic purposes. Additionally, ensure that redaction is NOT applied to primary application data stores where data integrity is required for business logic or legal compliance (e.g., LGPD records).

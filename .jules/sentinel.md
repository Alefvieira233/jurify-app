## 2026-05-20 - PII Leakage via Truncation & Weak ID Generation
**Vulnerability:** AI interaction logs were truncated to a fixed length (e.g., 500-2000 chars) *before* PII redaction was applied. Additionally, execution IDs were generated using insecure `Math.random()`.
**Learning:** Redacting PII after truncation is insufficient because sensitive data (like a 16-digit credit card or an OAB number) could be cut off at the boundary, potentially bypassing regex filters and leaving identifiable fragments in the database. Furthermore, using `Math.random()` for execution IDs increases collision risk and is not cryptographically secure for tracking sensitive AI operations.
**Prevention:** Always apply `redactPII` to the full text *before* performing any length-based truncation. For secure identifiers, use `crypto.randomUUID()`. A robust pattern for high-volume execution logs is `exec_${Date.now()}_${crypto.randomUUID().split('-')[0]}`, which provides both chronological ordering and high entropy collision resistance.

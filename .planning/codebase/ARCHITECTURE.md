## Overview

Jurify is a **Legal SaaS platform** built as a single-page application (SPA) with a serverless backend. The frontend is React 18 + TypeScript (strict mode) bundled with Vite. The backend is entirely Supabase: PostgreSQL with Row-Level Security, Edge Functions (Deno), Auth, Realtime, and Storage. There is no custom API server.

```
Browser (React SPA)
  |
  |-- Supabase JS Client (typed)
  |     |-- Auth (JWT, sessions)
  |     |-- Database (PostgREST + RLS)
  |     |-- Realtime (postgres_changes, presence)
  |     |-- Storage (documents, media)
  |
  |-- Supabase Edge Functions (32 Deno functions)
  |     |-- WhatsApp webhook, AI agents, Stripe, email, etc.
  |
  |-- External: Sentry, OpenAI, Kapso (WhatsApp), Stripe, ZapSign, Postmark
```

## State Management

### Server State: TanStack React Query
All server data flows through React Query. The global `QueryClient` (defined in `App.tsx`) uses:
- **2 retries** with exponential backoff (max 15s)
- **5-minute stale time**, 30-minute garbage collection time
- `refetchOnWindowFocus: false`

Data hooks follow a consistent pattern (example: `useLeads`):
```
Component -> useLeads() -> useQuery/useMutation -> Supabase JS client -> PostgREST -> PostgreSQL (RLS)
```

Every domain entity has a dedicated hook in `src/hooks/` (useLeads, useContratos, useAgendamentos, useProcessos, usePrazosProcessuais, useHonorarios, useDocumentosJuridicos, etc.) that encapsulates:
- Query with filtering/pagination
- CRUD mutations with optimistic updates
- RBAC checks via `useRBAC()`
- Toast notifications on success/error
- Sentry breadcrumbs for tracing

### Client State: React Context
Minimal client-side state is managed via React Context:
- **AuthContext** (`src/contexts/AuthContext.tsx`) -- user, session, profile (including role, tenant_id, subscription tier)

No Redux or Zustand is used. Component-local state uses `useState`/`useReducer`.

## Routing Architecture

### Router Setup
React Router v6 with `BrowserRouter`, wrapped by Sentry for navigation tracking (`Sentry.withSentryReactRouterV6Routing(Routes)`).

### Lazy Loading
All feature routes use `lazyWithRetry()` (`src/lib/lazyWithRetry.ts`), a custom wrapper around `React.lazy` that:
- Retries failed chunk imports up to 3 times (1.5s interval)
- Forces a single full page reload on final failure (handles deploy-time asset invalidation)
- Only reloads when the tab is visible (avoids false failures from throttled background tabs)

Critical routes (Auth, NotFound, ResetPassword) are eagerly imported. High-traffic routes (Pipeline, Scheduling, CRM, Reports, Processos, Prazos) are prefetched during browser idle via `requestIdleCallback`.

### Protected Routes & RBAC
`ProtectedRoute` (`src/components/ProtectedRoute.tsx`) wraps authenticated routes:
1. Shows loading spinner while auth state resolves
2. Redirects to `/auth` if no user
3. If `requiredRoles` prop is set, checks `profile.role` against allowed roles
4. Renders an "Access Denied" UI if role is insufficient

Role-restricted routes in the app:
- `admin` + `manager`: /usuarios, /logs, /auditoria, /honorarios, /equipe
- `admin` only: /admin/playground, /admin/mission-control, /admin/status

## Auth Architecture

### Flow
1. `AuthProvider` wraps the entire app inside `BrowserRouter`
2. On mount, calls `supabase.auth.getSession()` with a 15-second timeout
3. Listens to `onAuthStateChange` for session changes
4. On authenticated session, fetches profile from `profiles` table
5. Role is fetched separately from `user_roles` table (prevents privilege escalation via profile updates)
6. Profile includes: `id`, `nome_completo`, `email`, `role`, `tenant_id`, `subscription_tier`, `subscription_status`

### RBAC System
Defined in `src/types/rbac.ts`:
- **4 roles**: `admin`, `manager`, `user`, `viewer`
- **21 resources**: leads, contratos, agentes_ia, usuarios, configuracoes, relatorios, logs, integracoes, whatsapp, agendamentos, pipeline, processos, prazos, honorarios, documentos, conexoes, departamentos, tags, notificacoes, fluxos, regras
- **6 actions**: create, read, update, delete, execute, manage

The `useRBAC()` hook (`src/hooks/useRBAC.ts`) provides:
- `can(resource, action)` -- check a single permission
- `canAll(resource, actions)` / `canAny(resource, actions)` -- batch checks
- `canAccessResource(resource)` -- has any action on resource
- Role booleans: `isAdmin`, `isManager`, `isUser`, `isViewer`
- Convenience flags: `canManageUsers`, `canDeleteUsers`, `canManageConfig`, `canViewLogs`, `canExecuteAgents`
- **Department-scoped permissions**: `canInDepartment(departamentoId, action)` queries `departamento_membros` table for granular per-department access
- `getLeadVisibilityScope()` -- returns 'own' | 'department' | 'all'

### Multi-Tenancy
All database tables use a `tenant_id` column enforced by RLS policies. The database function `get_current_tenant_id()` extracts the tenant from the JWT. Golden RLS migration: `supabase/migrations/20260221000001_rls_golden.sql`.

## Error Handling Strategy

### Three Layers

1. **ErrorBoundary** (`src/components/ErrorBoundary.tsx`)
   - Class component wrapping every route and the entire app (double boundary in `main.tsx` and `App.tsx`)
   - Catches render errors, logs to Sentry with component stack
   - Shows user-friendly "Something went wrong" card with retry/reload buttons
   - Shows error details in development mode

2. **Sentry** (`src/lib/sentry.ts`)
   - Initialized in production only
   - Browser tracing, session replay (masked text, blocked media), user feedback widget
   - 10% trace sample rate in production
   - Global `unhandledrejection` and `error` window event handlers in `main.tsx`
   - Breadcrumbs added in data hooks for operation tracing

3. **Structured Logging** (`src/lib/logger.ts`)
   - `createLogger(module)` factory used throughout hooks and services
   - Namespaced log output (e.g., `[Leads]`, `[RealtimeSync]`)

### Utilities
- `src/utils/AppError.ts` -- custom error class
- `src/utils/validation.ts` -- input validation utilities
- `src/lib/monitoring.ts` -- performance monitoring

## Real-Time Features

### Supabase Realtime (`src/hooks/useRealtimeSync.ts`)
Activated globally in `Layout.tsx`. Subscribes to `postgres_changes` on core tables filtered by `tenant_id`:
- **Default tables**: leads, contratos, agendamentos, agent_executions, notificacoes
- On INSERT/UPDATE: optimistically updates React Query cache arrays in-place
- On DELETE: removes record from cache
- Invalidates related query keys (e.g., leads change also invalidates `dashboard-metrics-fast`)

### Realtime Presence (`useRealtimePresence`)
Tracks which users from the same tenant are online, using Supabase Presence channels with `user_id`, `user_name`, and `online_at`.

### Push Notifications
- `usePushNotifications` -- Capacitor push notifications for native app
- `useLocalPrazosNotifications` -- local browser notifications for deadline alerts
- `useRealtimeNotifications` -- real-time notification subscription

### Edge Function Flow
```

    -> Rate limiting (_shared/rate-limiter.ts)
    -> Business logic
    -> Supabase Admin Client for DB writes
    -> External APIs (OpenAI, Kapso, Stripe, etc.)
```

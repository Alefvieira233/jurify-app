## Security Concerns

### Priority: High
**RBAC is client-side only (Audit Finding 7)**

Role-based access control (`useRBAC()` + `ProtectedRoute`) is enforced exclusively in the React frontend. Supabase RLS filters by `tenant_id` but does NOT check `user_roles.role`. A user with `viewer` role who crafts direct Supabase queries can create/update/delete data.

- **Location:** `src/components/ProtectedRoute.tsx`, `src/types/rbac.ts`
- **Impact:** Any authenticated user within a tenant can bypass role restrictions.
- **Fix:** Add RLS policies that join `user_roles` to restrict write operations by role.

### Priority: High
**Dependency vulnerabilities (Audit Finding 5)**

`npm audit` flagged 3 high-severity issues in `@capacitor/cli` (tar: arbitrary file overwrite) and `@trapezedev/project` (replace: ReDoS). These are dev dependencies, so runtime risk is limited, but CI pipelines are exposed.

- **Status:** No upstream fix available yet for `@capacitor/assets`.
- **Mitigation:** Pin or override transitive dependencies if possible; monitor for upstream patches.

### Priority: Medium
**Rate limiter in-memory fallback is ineffective (Audit Finding 8)**

`supabase/functions/_shared/rate-limiter.ts` line 85 -- the `memoryStorage` Map resets on every Edge Function cold start. Since Supabase functions are stateless, the memory fallback provides no meaningful protection when the DB-based `check_rate_limit` RPC is unavailable.

### Priority: Medium
**CORS regex allows any `jurify-*` Vercel subdomain (Audit Finding 9)**

`supabase/functions/_shared/cors.ts` line 14 -- regex `/^https:\/\/jurify[-a-z0-9]*\.vercel\.app$/` matches any Vercel project starting with "jurify", including attacker-controlled ones like `jurify-malicious.vercel.app`.

- **Fix:** Tighten regex to match only known deployment hash patterns, e.g. `/^https:\/\/jurify(-[a-z0-9]{7,9})?(-alef-vieiras-projects)?\.vercel\.app$/`.

## Authentication Flow

### Supabase Auth (`src/contexts/AuthContext.tsx`)
1. Client initializes with `persistSession: true`, `autoRefreshToken: true`, `detectSessionInUrl: true`
2. `AuthProvider` checks for existing session with 15s timeout (covers slow connections)
3. After session established, fetches profile from `profiles` table and role from separate role table (prevents privilege escalation)
4. Exposes: `signIn`, `signUp`, `signOut`, `hasRole`, `hasPermission`
5. Inactivity logout via `useInactivityLogout` hook
6. Sentry user context set on auth state change

### RBAC
- **Permissions matrix**: `src/types/rbac.ts` (roles: UserRole, resources: Resource, actions: Action)
- **Client enforcement**: `src/components/ProtectedRoute.tsx` + `useRBAC()` hook
- **Server enforcement**: Row-Level Security (RLS) on all tables via `tenant_id` + `get_current_tenant_id()` function
- **RLS golden migration**: `supabase/migrations/20260221000001_rls_golden.sql`

## API Patterns

### Client-to-Supabase
- All DB queries via `@supabase/supabase-js` typed client (`src/integrations/supabase/client.ts`)
- Server state managed by TanStack React Query (`useQuery`, `useMutation`)
- Custom headers: `x-application-name: jurify`
- Edge Functions invoked via `supabase.functions.invoke('function-name', { body })`

### Edge Function-to-External API
- **Kapso (WhatsApp)**: REST via shared `kapsoFetch()` with `X-API-Key` header
- **OpenAI**: Via `openai` npm package (imported in Deno context)
- **Stripe**: Direct REST / Stripe SDK
- **ZapSign**: Direct REST with API token
- **Postmark**: Direct REST with server token

### CORS (`supabase/functions/_shared/cors.ts`)
- Default allowed origins: localhost (5173, 8080, 8081, 8082, 3000), `jurify.vercel.app`, `jurify-app.vercel.app`, `jurify.com.br`
- Dynamic matching: regex for any `jurify-*.vercel.app` deployment
- Configurable via `ALLOWED_ORIGINS` or `FRONTEND_URL` env vars
- Unknown origins receive `Access-Control-Allow-Origin: null`

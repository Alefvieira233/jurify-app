## Error Handling

### Layers
1. **ErrorBoundary** (React): wraps component trees, catches render errors, reports to Sentry
2. **Sentry** (`@/lib/sentry`): `initSentry()`, `captureException()`, `addSentryBreadcrumb()`, `setSentryUser()`
   - Production only, disabled in dev
   - Replay + tracing enabled
3. **Logger** (`@/lib/logger`): `createLogger('Module')` returns structured logger with `debug/info/warn/error`
   - Suppresses debug/info in production
4. **Toast** (`@/hooks/use-toast`): user-facing notifications via sonner
5. **AppError** (`@/utils/AppError`): custom error class for typed application errors

### Pattern
```typescript
const log = createLogger('Leads');
try {
  // Supabase operation
  addSentryBreadcrumb('lead_created', { leadId });
} catch (error) {
  log.error('Failed to create lead', { error });
  toast({ title: 'Erro', description: '...', variant: 'destructive' });
}
```

## File Organization

### Top-Level Structure
```
src/
  components/        # Shared components (ui/, forms/, auth/, billing/, etc.)
  contexts/          # React contexts (AuthContext.tsx)
  features/          # Feature modules (30 feature directories)
  hooks/             # Shared hooks (50+ hooks)
  integrations/      # External service clients (supabase/)
  lib/               # Libraries (logger, sentry, security, legal, multiagents)
  pages/             # Standalone pages (TermosDeUso, Pricing, etc.)
  schemas/           # Zod validation schemas
  types/             # TypeScript type definitions (rbac.ts, crm-operacional.ts)
  utils/             # Utility functions (validation, formatting, encryption)
  tests/             # Integration tests and test setup
```

### Feature Module Structure
Each feature in `src/features/{name}/` contains:
- Main component (e.g., `Dashboard.tsx`)
- `components/` subdirectory for child components
- `__tests__/` subdirectory for feature-level tests

### RBAC
- Roles: `admin`, `manager`, `user`, `viewer` (defined in `src/types/rbac.ts`)
- Permission matrix: `ROLE_PERMISSIONS` maps roles to resource-action pairs
- Client-side: `useRBAC()` hook provides `can(resource, action)` helper
- Route protection: `<ProtectedRoute requiredRoles={[...]}>`
- Server-side: RLS policies in Supabase with `tenant_id` isolation

### Edge Functions
- 32 Edge Functions in `supabase/functions/`
- Shared utilities in `supabase/functions/_shared/` (cors, rate-limiter, etc.)
- Migrated to `Deno.serve` native pattern

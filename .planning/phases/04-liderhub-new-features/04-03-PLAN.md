
    Hook `useStatusManager()`:
    - Query: fetch from crm_pipeline_stages where tenant_id = tenantId, order by position ascending. QueryKey: ['status-stages', tenantId].
    - Also fetch lead counts: for each stage, do a single bulk query on leads table grouping by pipeline_stage_id (same pattern as useCRMPipeline). Return as Map<stageId, count>.
    - `createStage` mutation: accepts `{ name: string; color: string; is_won?: boolean; is_lost?: boolean; auto_followup_days?: number | null }`. Generate slug from name using: `name.toLowerCase().replace(/\s+/g, '-').replace(/[^a-z0-9-]/g, '')`. Set position to max(existing positions) + 1. Insert into crm_pipeline_stages with tenant_id. Invalidate query on success. Toast "Status criado".
    - `updateStage` mutation: accepts `{ id: string; name?: string; color?: string; position?: number; is_won?: boolean; is_lost?: boolean; auto_followup_days?: number | null }`. If name changes, also update slug. Update in crm_pipeline_stages. Invalidate query on success.
    - `deleteStage` mutation: accepts id string. Delete from crm_pipeline_stages where id. Invalidate query on success. Toast "Status removido".
    - `reorderStages` mutation: accepts `{ id: string; position: number }[]`. For each item, update position. Invalidate query on success.
    - Return: `{ stages, leadCounts, isLoading, createStage, updateStage, deleteStage, reorderStages }`

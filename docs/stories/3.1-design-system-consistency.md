# Story 3.1: Normalizacao de Banco de Dados e Compliance LGPD

## Status: Draft
## Sprint: 3
## Estimativa: 30 horas
## Prioridade: P2

## Descricao

Normalizar dados duplicados no banco de dados (3 sistemas de tags, colunas duplicadas em whatsapp_messages, scores duplicados em leads, coluna responsavel legada), implementar soft-delete consistente para compliance LGPD, adicionar redacao PII em logs de IA (dados juridicos sensiveis em plaintext), e criar politica de retencao para tabelas de log. Esta story elimina as maiores fontes de inconsistencia de dados e prepara o sistema para compliance LGPD completo.

- **DEB-033:** Coluna responsavel text duplicada em contratos (2h) -- LOW

## Notas Tecnicas

### Tag Migration Strategy
```sql
-- Migrar crm_tags -> tags
INSERT INTO tags (id, nome, cor, categoria, tenant_id, ...)
SELECT gen_random_uuid(), nome, cor, 'crm', tenant_id, ...
FROM crm_tags
ON CONFLICT DO NOTHING;

-- Mapeamento de IDs para migrar junctions
CREATE TEMP TABLE tag_id_map AS
SELECT ct.id as old_id, t.id as new_id
FROM crm_tags ct JOIN tags t ON ct.nome = t.nome AND ct.tenant_id = t.tenant_id;
```

### PII Redaction Function
```sql
CREATE OR REPLACE FUNCTION redact_pii(input TEXT) RETURNS TEXT AS $$
BEGIN
  -- CPF: 123.456.789-01 -> ###.###.###-##
  input := regexp_replace(input, '\d{3}\.\d{3}\.\d{3}-\d{2}', '###.###.###-##', 'g');
  -- Numero de processo: 1234567-89.2023.8.26.0100
  input := regexp_replace(input, '\d{7}-\d{2}\.\d{4}\.\d\.\d{2}\.\d{4}', '[PROCESSO REDACTED]', 'g');
  RETURN input;
END;
$$ LANGUAGE plpgsql IMMUTABLE;
```

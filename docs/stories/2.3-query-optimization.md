# Story 2.3: Fundacao de Acessibilidade (WCAG 2.1 Level A)

## Status: Draft
## Sprint: 2
## Estimativa: 26 horas
## Prioridade: P1

## Descricao

Implementar os requisitos basicos de acessibilidade WCAG 2.1 Level A: skip-to-content para screen readers, aria-live para feedback dinamico em formularios e listas, e navegacao completa por teclado em tabelas e kanban. A Lei Brasileira de Inclusao (Lei 13.146/2015) exige acessibilidade em servicos digitais, e escritorios publicos (advocacia publica, defensorias) tem obrigacao legal explicita. Atualmente, o codebase tem apenas 8 ocorrencias de `tabIndex`/`onKeyDown` e 2 de `aria-live`.

- **DEB-046:** aria-live ausente em feedback dinamico (6h) -- MEDIUM

## Notas Tecnicas

### Padrao de Keyboard Navigation para Tabelas
```tsx
const handleKeyDown = (e: React.KeyboardEvent, rowIndex: number) => {
  switch (e.key) {
    case 'ArrowDown':
      e.preventDefault();
      focusRow(rowIndex + 1);
      break;
    case 'ArrowUp':
      e.preventDefault();
      focusRow(rowIndex - 1);
      break;
    case 'Enter':
      e.preventDefault();
      openDetail(rows[rowIndex]);
      break;
    case 'Escape':
      e.preventDefault();
      (e.target as HTMLElement).blur();
      break;
  }
};
```

### Padrao ARIA para Listas Filtraveis
```tsx
<div>
  <input type="search" aria-controls="results-list" />
  <ScreenReaderAnnounce message={`${filteredCount} resultados encontrados`} />
  <div id="results-list" role="list" aria-label="Lista de contatos">
    {/* items */}
  </div>
</div>
```

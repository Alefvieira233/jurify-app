# Story 4.2: Bundle Optimization, Foreign Keys e Column Projection

## Status: Draft
## Sprint: 4
## Estimativa: 12 horas
## Prioridade: P2/P3

## Descricao

Otimizar os dois maiores chunks do bundle (Sentry 445KB e Recharts 457KB), adicionar foreign keys ausentes em tabelas utilitarias para integridade referencial, implementar column projection na tabela leads (47 colunas) como quick win de performance, e documentar a convencao de naming PT/EN via ADR.

## Debitos Incluidos

- **DEB-036:** Sentry bundle size 445KB -> ~200KB (4h) -- LOW
- **DEB-037:** Recharts bundle size 457KB (3h) -- LOW
- **DEB-031:** Foreign keys ausentes em tabelas utilitarias (3h) -- LOW
- **DEB-016:** leads column projection -- quick win (2h) -- MEDIUM

### DEB-031: Foreign Keys (3h)
- [ ] Auditar tabelas utilitarias sem FKs:
  ```sql
  SELECT table_name FROM information_schema.tables
  WHERE table_schema = 'public'
  AND table_name NOT IN (SELECT DISTINCT tc.table_name FROM information_schema.table_constraints tc WHERE constraint_type = 'FOREIGN KEY');
  ```
- [ ] Para cada tabela, verificar se dados existentes sao validos (FK nao falhara)
- [ ] Criar migration com FKs:
  ```sql
  ALTER TABLE api_keys ADD CONSTRAINT fk_api_keys_tenant FOREIGN KEY (tenant_id) REFERENCES tenants(id);
  ALTER TABLE assistant_audit ADD CONSTRAINT fk_assistant_audit_profile FOREIGN KEY (user_id) REFERENCES profiles(id);
  -- etc.
  ```
- [ ] Testar migration em ambiente local
